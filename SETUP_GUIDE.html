Architecture Overview

Two-server setup on one domain — NGINX routes requests to the right place:

Browser
  ↓ HTTPS / WSS  (watch.relay.media)
NGINX on VPS
  ├── /api/*  →  Node.js (port 3001) — REST API
  ├── /ws     →  Node.js (port 3001) — WebSocket signaling
  └── /*      →  Static HTML/CSS/JS files (public/ directory)

Static files can be served either by NGINX on the VPS or uploaded directly to cPanel's public_html. Either works — NGINX only needs to handle /api and /ws.

1. VPS Setup

Tested on Ubuntu 22.04 LTS. Run as root or with sudo.

1Update system and install Node.js 20 LTS
apt update && apt upgrade -y
curl -fsSL https://deb.nodesource.com/setup_20.x | bash -
apt install -y nodejs nginx mysql-server git certbot python3-certbot-nginx
node --version   # should print v20.x.x
2Create app user and directory
useradd -r -s /bin/false streamparty
mkdir -p /var/www/streamparty/{server,public,uploads}
chown -R www-data:www-data /var/www/streamparty

2. Database Setup

1Secure MySQL and create database
mysql_secure_installation   # follow the prompts

mysql -u root -p <<'SQL'
CREATE DATABASE streamparty CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
CREATE USER 'streamparty'@'localhost' IDENTIFIED BY 'CHOOSE_A_STRONG_PASSWORD';
GRANT ALL PRIVILEGES ON streamparty.* TO 'streamparty'@'localhost';
FLUSH PRIVILEGES;
SQL
2Import schema
mysql -u streamparty -p streamparty < /var/www/streamparty/server/schema.sql

3. Deploy Node App

1Copy server files to VPS

From your local machine (or git clone):

# Option A — rsync from local
rsync -avz ./server/ root@your-vps-ip:/var/www/streamparty/server/

# Option B — git
cd /var/www/streamparty
git clone https://github.com/YOUR/REPO.git .
# then copy server/ files to /var/www/streamparty/server/
2Install Node dependencies
cd /var/www/streamparty/server
npm install --omit=dev
chown -R www-data:www-data /var/www/streamparty

4. Configure NGINX

1Install the config
cp /var/www/streamparty/nginx.conf /etc/nginx/sites-available/streamparty
ln -s /etc/nginx/sites-available/streamparty /etc/nginx/sites-enabled/streamparty
rm -f /etc/nginx/sites-enabled/default   # remove default site if present
nginx -t   # test config
⚠️ Don't start NGINX yet — get the SSL cert first (next step).

5. SSL Certificate

1Get free SSL via Let's Encrypt
# Temporarily serve on port 80 for cert verification
# Make sure DNS A record for watch.relay.media points to this VPS IP

certbot --nginx -d watch.relay.media

# Certbot auto-edits your nginx.conf with SSL paths
# Auto-renewal is configured automatically
✓ Certbot handles renewal. Certs expire every 90 days but renew automatically.

6. cPanel — Upload Static Files

The HTML/CSS/JS files can be hosted directly on your cPanel shared hosting — this is optional if NGINX serves them from /var/www/streamparty/public.

Option A — cPanel hosts the static files

  1. In cPanel File Manager, navigate to public_html (or the domain's document root)
  2. Upload the contents of the public/ folder — all .html files, css/, and js/ subdirectories
  3. In the NGINX config (nginx.conf), comment out the root and location / block — NGINX only proxies /api and /ws
  4. Make sure the cPanel domain and the VPS domain are the same hostname (watch.relay.media) — DNS should point to the VPS IP so NGINX handles all traffic, then NGINX can either serve static files locally or reverse-proxy to cPanel's Apache port 8080

Option B — VPS serves everything (simpler)

  1. Copy public/ to /var/www/streamparty/public/ on the VPS
  2. The nginx.conf already has root /var/www/streamparty/public
  3. No cPanel involvement needed for file serving
✓ Option B is simpler and recommended. Use cPanel only if you prefer managing files through its File Manager.

7. Environment Variables

1Create the env file
cp /var/www/streamparty/streamparty.env.example /etc/streamparty.env
chmod 600 /etc/streamparty.env
nano /etc/streamparty.env

Required values to change:

VariableValue
DB_PASSThe MySQL password you set in step 2
JWT_SECRETLong random string — run: node -e "console.log(require('crypto').randomBytes(48).toString('hex'))"
ORIGINhttps://watch.relay.media
UPLOAD_DIR/var/www/streamparty/uploads

8. Start the Service

1Install and start systemd service
cp /var/www/streamparty/streamparty.service /etc/systemd/system/
systemctl daemon-reload
systemctl enable streamparty
systemctl start streamparty
systemctl status streamparty   # should show "active (running)"
2Start NGINX
systemctl enable nginx
systemctl start nginx
nginx -s reload

9. Verify Everything Works

1Check API health
curl https://watch.relay.media/health
# Expected: {"status":"ok","rooms":0,"guests":0,"uptime":...}
2Check WebSocket
# Install wscat: npm install -g wscat
wscat -c wss://watch.relay.media/ws
# Expected: {"type":"hello","peerId":"..."}
3Visit the site

Open https://watch.relay.media — you should see the browse page. Static files are served, API calls to /api/* work, and WebSocket connects on stream pages.

cd /var/www/streamparty/server
# (copy/rsync new files)

# Install any new dependencies
npm install --omit=dev

# Restart server (zero downtime with systemd)
systemctl restart streamparty

# For static file updates (public/):
# Just copy the new files — no restart needed

Troubleshooting

Node app not starting

journalctl -u streamparty -f    # live logs
journalctl -u streamparty -n 100  # last 100 lines

NGINX errors

nginx -t                           # test config syntax
tail -f /var/log/nginx/streamparty.error.log

Database connection refused

systemctl status mysql
mysql -u streamparty -p -e "SELECT 1;"   # test connection

WebSocket not connecting

  • Check that Upgrade and Connection headers are set in the NGINX location block
  • Make sure firewall allows port 443: ufw allow 443
  • Verify proxy_read_timeout is at least 3600s for the /ws location

Snapshots not saving

  • Check UPLOAD_DIR is writable by www-data: ls -la /var/www/streamparty/uploads
  • Fix: chown www-data:www-data /var/www/streamparty/uploads

Screen share not working in Safari

Safari on iOS does not support getDisplayMedia. Cam and file source work fine on mobile. Screen share is a desktop-only feature.
